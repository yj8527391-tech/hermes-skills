# 中文学术引用格式规范化（GB/T 7714 顺序编码制）

任何中文论文、开题报告、期刊投稿、课程作业，只要正文要标引用、文末要列参考文献，走这套。条文是查证过的标准原文，不是凭印象。

## 一、顺序编码制两条硬规定

**第 9.2.1.1 条**：按正文中引用文献出现的先后顺序连续编码，序号置于方括号 `[ ]` 中。标准给出的示例全部用**上标**形式。

**第 9.2.1.2 条**：同一处引用多篇文献时，各序号在同一个方括号内**全部列出**，序号间用逗号；如遇连续序号，起讫序号间用**短横线**连接。

由此推出来的写法：

| 场景 | 正确 | 常见错误 |
|---|---|---|
| 单篇 | `……判断依据[7]。` | 与正文同高，没设上标 |
| 两篇连续 | `[5-6]` | `[5][6]` |
| 三篇连续 | `[2-4]` | `[2][3][4]` |
| 连续加断档 | `[7-8,10]` | `[7][8][10]` |
| 两篇不连续 | `[7,11]` | `[7][11]` |
| 序号位置 | 句末标点**之前** | 标点之后 |

版本说明：现行版是 GB/T 7714—2025，2026 年起实施，这两条与 2015 版无实质差异。学校文件多半还写 2015，按 2015 写最稳。

## 二、各类型文献著录格式

作者规则：三人以内全列，超过三人列前三加“等”（中文）或“et al.”（英文）。各项之间用实心句点分隔，条目末尾也带句点。

```
期刊 [J]     作者. 题名[J]. 刊名, 年, 卷(期): 起页-止页.
专著 [M]     作者. 书名[M]. 版次. 出版地: 出版者, 年: 页码.
学位论文 [D] 作者. 题名[D]. 城市: 学校, 年.
报纸 [N]     作者. 题名[N]. 报纸名, 出版日期(版次).
行业报告 [R] 编者. 题名[R]. 出版地: 出版者, 年.
析出文献 [C] 作者. 题名[C]//编者. 文集名. 出版地: 出版者, 年: 页码.
电子资源     作者. 题名[EB/OL]. (发布日期)[引用日期]. URL.
```

实例对照：

```
[3] 金震. 论游戏音乐的工业化特质[J]. 中国音乐学, 2011(2): 107-111.
[5] 张新衢. 本土游戏音乐的发展历程研究[D]. 长春: 吉林艺术学院, 2024.
[6] 张听雨. 游戏音乐，与古典音乐汇流[N]. 音乐周报, 2022-08-10(005).
```

报纸那条最容易漏版次，只写日期不写 `(005)` 是不全的。查不到版次就如实说明按检索所见状著录，别编一个号上去。

## 三、程序化处理（推荐，别手工点上标）

生成器写进 docx 的 `[n]` 默认是普通文字。手工选中点几百次上标不现实，用脚本：

```bash
# 一步到位：合并连续序号 + 全部设上标
python scripts/normalize_refs.py 论文.docx 开题.docx

# 只检查不改动
python scripts/normalize_refs.py --check 论文.docx
```

脚本逻辑三层：正则定位 `\[[\d,\-]+\]`；判断当前段落是不是参考文献条目（以 `[n]` 开头且含 `[J]/[M]/[D]` 类型标识或长度超 60）就整段跳过不上标；其余把文字块按标记拆开，标记部分单独设 `superscript=True`，格式从原文字块复制继承。

处理完必须回检，别只看脚本 exit 0。检查项：文献条数、正文引用处数、其中已上标数、有没有漏标、文献条目有没有被误上标。`--check` 会报这几项。

## 四、交付前必查的三件事

**一、正文零引用。** 文献表列了十几条，正文一个 `[n]` 都没有，是最常见的硬伤。生成器把参考文献渲染成文末清单，正文却没接上。查法：统计正文引用号集合，与文献条数对齐，缺一条都得回去补引用位置，不许让文献挂空。

**二、多稿之间文献表不一致。** 开题报告 15 条、综述 14 条这种，同一批材料交上去很容易被看出来。补法不是删掉多的那条，而是给少的那条在正文补一处**真实用途**，说明它为什么在这，两边都留满。

**三、Word 保存后上标还在不在。** `font.superscript` 是 run 级格式，Word 更新域、重排后一般不掉，但要抽查一次。重跑一遍 `--check` 最省事。

## 五、踩过的坑

- 合并连续序号不能只看数字相邻，要先确认这几篇是**同一句话里的并列引用**，不是两个不同位置被误粘。批处理前把每处合并的上下文念一遍。
- 参考文献条目必须以 `[n]` 开头加类型标识判定，只按长度判会把长段落上标错。反过来只按类型标识判会漏掉没写 `[J]` 的条目，两个条件取或。
- Word 里表格合并单元格会让同一段落在遍历时被返回多次，统计数字翻倍。但去重**别用 `id(p._p)`**：lxml 的元素代理对象会被回收，`id()` 可能被复用，段落被误判成“已处理”而整段跳过。实测症状是 15 条参考文献只识别出 3 条、正文引用一处都没扫到。把元素本身当 set key：`if p._p not in seen: seen.add(p._p)`。
- 用 `re.split` 切引用标记时，正则里**不能有捕获组**。`re.compile(r'\[([\d,\-]+)\]').split('…[5-6]。')` 返回 `['', '5-6', '。']`，中间那个 `5-6` 是捕获内容，当普通文字插回去页面上就会出现 `[5][6]5-6` 这种残留。要备两个正则：带捕获的 `findall` 取编号，无捕获的 `split` 切文字。
- 引用处理脚本必须幂等。已经是域的文档再跑一遍，会把域结果外层的 run 又套一层域，文档直接坏。处理前扫 `fldChar` 维护域深度，深度大于 0 的 run 一律跳过。
- 文件被 Word 或 WPS 占着时 python-docx 保存报 `PermissionError`。先存到临时目录跑完流程验证，再覆盖原位置，别把没验证的半成品顶上去。
- Word COM 打开文档处到第二个就报 `unknown.Open`，一个进程只能开一个文档，批量处理要分进程跑。

## 六、交叉引用域：让编号增删后自动重排

上标只是外观。真正要让正文编号跟着文献表变，得做成 Word 交叉引用域。老师或学生拿来的“规范模板”里那串上标，很多就是域而不是文字，用 python-docx 读出来才发现。

### 三层结构，缺一件就不动

| 层 | 位置 | 做法 |
|---|---|---|
| 一 | 参考文献段落 | 用自动编号，`numPr` 挂到 `lvlText="[%1]"` 的编号定义，文字里**不再留**手打 `[1]` |
| 二 | 每条文献 | 包一个书签 `_Ref21842`（下划线开头加五位数字） |
| 三 | 正文引用 | 五个 run 拼一个域：`begin` → `instrText` 写 ` REF _Ref21842 \r \h ` → `separate` → 结果 run → `end` |

`\r` 插段落编号（因为 `lvlText` 是 `[%1]`，结果自带方括号），`\h` 生成超链接可点击跳转。**五个 run 都要带 `vertAlign=superscript`**，否则域结果不上标。

### 与国标 9.2.1.2 的真实冲突（必须当面告知使用者）

`\r` 和 `\n` 都输出带方括号的编号，`\n` 只是去掉编号后的制表符，去不掉括号。所以多个引用拼不成 `[5-6]`，硬拼只会得到 `[5]-[6]` 或手写括号与域括号叠成 `[[5]]`。可行形态只有每个编号一个独立域，连着排，显示 `[5][6]`。

| 方案 | 优点 | 缺点 |
|---|---|---|
| 独立域 `[5][6]` | 增删文献全篇自动重排 | 不完全符合 9.2.1.2 合并要求 |
| 定稿手动合并 `[5-6]` | 格式完全合规 | 合并处变死文字，之后再改文献不跟着变 |

实际做法：写作阶段用独立域，交学校那版再手动合并。定稿后文献不再动，死文字没风险。已经给学生用过的模板如果就是独立域形态，保持一致更稳，不要自作主张改。

### 验证：必须故意删一条试

看着对不算。删掉中间一条参考文献，Word 里 `Ctrl+A` + `F9` 更新域，再看正文：原 `[5][6]` 应变 `[4][5]`，原 `[7][8][10]` 应变 `[6][7][9]`，原 `[15]` 应变 `[14]`，文献表 1—15 变 1—14。全部跟着动才算通。测完用副本还原。

### 交付后要告知的两句话

1. 改文献后按 `Ctrl+A` 再 `F9`，编号自动重排，不要手改数字。
2. 跨文档复制粘贴可能断链（显示“错误！未找到引用源”），要粘贴时选“保留源格式”或重新做域。
