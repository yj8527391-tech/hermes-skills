# 批量企业背调（招聘会 / 供应商 / 合作方）

> 一次真实任务：125 个展位 / 124 家公司，从四张展位名录照片到「12 个重点展位 + 全量可筛选表」，全程约 50 分钟、6 个子 agent。详见 `references/job-fair-case-2026-11.md`。

## 一、先定结构：三轮筛选

| 轮次 | 做的事 | 覆盖 | 输出去向 |
|:--|:--|:--|:--|
| **R1 排雷** | 工商底子 + 招聘性质 + 负面，打风险分 | 全量（100%） | 淘汰 / 观察 / 通过 |
| **R2 验货** | 真实业务（项目/中标）、团队规模、岗位是否销售、具体薪资福利 | 15–25 家 | 每家一段证据化点评 |
| **R3 比价** | 对比待遇结构、成长性、通勤，给 A/B/C 梯队 | 10–15 家 | 推荐清单 + 走场路线 |

**R1 打分规则（0–10，分高＝越像野鸡）**：成立≤2 年 +3；注册资本<100 万 +2（<10 万 +3）；参保 0–3 人 +3；经营状态异常 +5；失信/被执行/欠薪仲裁 +5；经营范围与招聘岗位严重不符 +3；人力资源/企业管理/劳务派遣类无名企背景 +3；常年招主播/模特/艺人 +3；医美地推/贷款中介/电销 +3；招聘收费/培训贷投诉 +5。**体制内、上市/知名集团 −2~−3**。结论：≥6 淘汰，4–5 观察，≤3 通过。

## 二、采集：每家只问 1–2 个高价值查询

引擎耐用度、选择器、反爬对策见 **web-scraper** 技能 §5d（企业背调数据源）。速记：

| 源 | 适合 | 耐用度 |
|:--|:--|:--|
| 头条 `so.toutiao.com/search?keyword=` | 招聘岗位+待遇+中标+舆情（一网打尽） | 80+ 家未封 |
| 神马/夸克 `m.sm.cn/s?q=` | 水滴信用企业卡片：成立/注册资本/地址/经营范围 | 约 30–40 次 |
| 搜狗（**公司全名加引号**） | 首条即企查查卡片 | 约 60 次 |
| 360 / 天眼查 | 数据最全但最脆 | ~150 次 / **3 次** |

铁律：**数据不足就写“未检索到”，绝不编注册资本/参保人数/成立时间**。企查查类平台数据有滞后，报告末尾要写免责。

## 三、多子 agent 分工（不要自己串行爬）

- **抓取与初判同包**：每个子 agent 拿 30–45 家，跑自家脚本抓完 → 读结果 → 写 CSV。串行爬 124 家约 30 分钟，2 个子 agent 并行约 8 分钟（使用者会催“怎么这么慢”）。
- **CSV schema 固定**（否则合并时要重构）：
  `id,name,est_year,reg_capital,status,business,fit_post,fit_level,risk_score,verdict,reason,evidence`
- 子 agent 提示词必须给：① 客户/求职者画像；② 对口语义词表；③ 打分规则；④ 路径与字段；⑤“严禁编造，写未检索到”；⑥ 补充查询上限（5–8 次/人，防止把引擎刷封）。
- **并发上限受配置限制**（本机 2 个），按 2 人一波滚。
- **监督**：子 agent 卡在 `process(wait)` 超 3–5 分钟无新增输出 → `action=stop` 接管，自己补抓/自己判，别干等。
- **归一化**：R1 子 agent 天生爱给“观察”（本次 74/124），把「观察 + 风险≤3 + 对口高/中」视为通过再进 R2，否则被软判定淹掉。

## 四、交付物（使用者只看 docx / xlsx）

1. **报告 .docx**：先用 markdown 写（结论先行 → 客户画像 → 方法 → 分层名单 → A/B 档逐家 → 比价基准 → 行动路线 → 简历/自我介绍建议 → 数据来源与局限），再 `python "<脚本目录>/md2docx.py" report.md out.docx`（支持标题/加粗/列表/真表格）。
2. **全量表 .xlsx**：`templates/build_xlsx.py` 改三个路径即可（表头深色、结论配色、冻结窗格、自动筛选、统计页）。
3. 表格要求：每家一行可筛选，列里必须有“结论 + 梯队 + 依据 + 证据来源”，别只给分数。
4. **发到微信**（使用者常用验收方式，2026-11 实测）：使用者说“发我微信”→ 用 `wechatauto` 的 `wx.ChatWith(会话)` + `wx.SendFiles([xlsx, docx])`；本机只登主号时默认发「微信ClawBot」会话。发完**必须回读 DB**（`db.get_messages(<username>, limit=N)` 里能看到 `<title>文件名</title>`）再告诉使用者已发送——`SendFiles` 返回的“成功”不可信。完整坑位见 `windows-gui-automation` → `references/wechat.md`。

## 五、坑位清单

| 坑 | 修法 |
|:--|:--|
| 名录是照片，OCR 有错字/重复 | 同一主体多展位要先去重（本次 A123=A069，另有 3 个同系主体），报告开头声明“按去重后 N 家计” |
| **名企滤镜** | 总部岗位≠本地岗位：外地国企在本地只招演员/销售、头部 MCN 当地没办公点——R2 必查“岗位 base 在哪、有没有实体” |
| 分公司/加盟店 | 看总公司实力，但招聘主体是分公司时社保/合同要单独确认 |
| 教培/公考机构 | “新媒体/教务/班主任”大概率含招生销售指标，必须问“背不背 KPI” |
| 薪资只有一个区间 | 补查职友集/应届生求职网/BOSS 三处取交集；写清“底薪 vs 综合” |
| 福利写“三险” | 五险一金缺失的硬信号，直接降档 |
| 只给“观察”没有结论 | 客户要可执行名单：必须落成 A/B/C/不推荐/可略过 |
| 引擎中途返回空 | 不是没数据，是被限流；换引擎/降频/隔 20 分钟，别把空结果当事实写进表里 |
| 子agent给的薪资/规模直接写进报告 | 关键数字（薪资区间、参保人数、营收）自己再查一遍：本次 A067 被子agent写成 8–12K，实测智联/BOSS 是 6–11K、云南中心公告 7–10K，宁可写保守 |
| 异步回执晚到（delegation 完成通知） | 先查产物文件是否已存在/已 merge（看时间戳），已并入就只确认不回滚重跑 |

## 六、完成前自检

- [ ] 全量行数 = 去重后公司数（缺一个都要补）
- [ ] 所有字段非空：没数据写“未检索到”，不是空字符串
- [ ] 梯队覆盖全量（不留“未分级”）
- [ ] docx 里是真表格（`document.xml` 中 `<w:tbl>` 数量 > 0）
- [ ] A 档每家都有“现场必问”的一句话
